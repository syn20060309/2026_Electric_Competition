# MPU6050 加速度 OLED 调试与任务调度设计

## 目标

在现有小车工程中周期读取 MPU6050 的 X/Y 轴加速度，并以 `g`
为单位显示在 OLED 上。比赛运行期间同时保留状态和计时显示，不增加
周期串口输出，不改变巡线算法、巡线调用频率、速度、PID 或自动停车逻辑。

## OLED 页面

OLED 使用四行显示：

```text
RUNNING
AX:+0.008g
AY:-0.003g
T:12.34s
```

- 第 0 行显示比赛状态：`IDLE`、`RUNNING`、`STOPPED`、`FINISH`、
  `ABORT` 或 `TIMEOUT`。
- 第 2 行显示 X 轴加速度。
- 第 4 行显示 Y 轴加速度。
- 第 6 行在 `IDLE` 时显示 `PRESS KEY`，其他状态显示当前或最终时间。
- 加速度显示保留三位小数，并包含正负号。
- 读取失败时显示 `AX:---` 和 `AY:---`，避免把旧数据当成新数据。

## 加速度采样

新增独立的 MPU6050 加速度任务。每次任务通过一次连续寄存器读取同时取得
X、Y、Z 三轴原始值，不为 X 和 Y 分别发起软件 I2C 事务。

当前加速度量程为正负 2g，换算关系为：

```text
acceleration_g = raw / 16384.0
```

加速度任务每 30ms 执行一次，保存最新原始值、换算后的 X/Y `g` 值以及
本次样本是否有效。OLED 只读取任务保存的快照，不直接访问 MPU6050。

驱动层提供能够报告成功或失败的三轴读取接口。保留现有
`MPU6050ReadAcc()` 接口，避免破坏已有调用。

## 调度器

新增 `task.c/.h`，定义任务结构和非阻塞调度入口：

```c
typedef struct {
    uint32_t interval;
    uint32_t last_call;
    void (*task)(void);
} Task;

void Scheduler_Run(void);
```

任务表为：

```c
Task tasks[] = {
    {10,  0, Key_Handle},
    {30,  0, MPU6050_AccelTask},
    {100, 0, OLED_RefreshTask},
};
```

- 按键保持 10ms 调度周期，以符合现有 20ms 消抖逻辑并避免漏掉短按。
- MPU6050 每 30ms 采样一次。
- OLED 每 100ms 刷新一次。
- 调度器使用无符号时间差判断到期，正确处理 32 位毫秒计数回绕。
- 任务执行后将 `last_call` 更新为当前时间，不连续补跑错过的周期。
- `Get_Odometry` 不加入任务表，因为当前工程没有对应接口。

## 主循环

主循环调用调度器，但巡线继续在每一轮主循环执行：

```c
while (1)
{
    Scheduler_Run();

    if (g_LinePortal_flag)
    {
        LineWalking();
    }
}
```

`LineWalking()` 不放入定时任务表，避免改变现有巡线响应速度。原来主循环
中的 `Key_Handle()` 和 `OLED_Task()` 由调度器负责调用。

## 模块边界

- `task.c/.h`：只负责周期调度，不读取传感器或绘制页面。
- MPU6050 加速度任务：只负责一次三轴采样、单位换算和发布最新快照。
- MPU6050 驱动：执行一次连续六字节读取并返回明确的成功或失败结果。
- OLED 任务：读取加速度快照、比赛计时和比赛状态，生成四行页面。
- `empty.c`：初始化现有模块并在主循环调用 `Scheduler_Run()` 与
  `LineWalking()`。

## 错误处理

- 单次 MPU6050 读取失败不会阻塞主循环，也不会重新执行 DMP 初始化。
- 失败样本标记为无效，OLED显示占位符；后续读取成功后自动恢复正常显示。
- OLED自身不可用时沿用现有策略：OLED任务停止写屏，其他任务继续运行。
- 调度器不执行延时等待，不在中断中进行软件 I2C 或 OLED传输。

## 验证

- 主机测试验证调度周期、首次触发行为以及 32 位时间回绕。
- 主机测试验证一次采样同时更新 X/Y、正负数换算和读取失败状态。
- 扩展 OLED测试，验证 `IDLE`、`RUNNING`、`STOPPED`、`FINISH`、
  `ABORT` 和 `TIMEOUT` 页面同时包含正确的加速度与提示或时间。
- 使用 SysConfig CLI确认引脚配置未变化。
- 使用 TI Arm Clang执行强制全量编译，修复所有新增错误和警告。
- 实物验证静止零偏、显示刷新稳定性，以及巡线过程中未出现响应速度下降。
