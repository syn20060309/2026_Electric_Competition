# MPU6050 Software I2C Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add MPU6050/DMP initialization using PA24 as SCL and PA25 as SDA without changing the existing vehicle peripherals or control logic.

**Architecture:** SysConfig owns the two GPIO resources and initializes them high. The MPU6050 bus driver implements open-drain behavior in software by enabling output only for a low level and disabling output to release a high level. `empty.c` initializes the sensor and retries DMP initialization before continuing the existing application startup.

**Tech Stack:** MSPM0G3507 DriverLib, TI SysConfig, TI Arm Clang, InvenSense eMPL/DMP, C11 host tests.

## Global Constraints

- PA24 is SCL and PA25 is SDA.
- PA24/PA25 use standard GPIO, not unsupported hardware OD I/O structure.
- I2C pull-ups are external and connect to 3.3 V only.
- Existing OLED, tracking sensor, motor, key, buzzer, timer, PID, and lap-finish behavior remain unchanged.
- Generated SysConfig files are never edited manually.
